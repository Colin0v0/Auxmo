- 正在使用的输出、麦克风以及多设备输出成员不可隐藏；隐藏设备不会出现在普通设备列表或应用路由菜单中。

- 补齐隐藏设备、状态提示和动态错误的英文文案。

## 0.4.0 Auxmo 新品牌与全局安全静音

- 产品、Swift target、Bundle ID、日志与配置键、构建环境变量、资源和发布资产统一迁移到 Auxmo；0.4.0 使用 `com.colin0v0.auxmo.app`，不迁移旧品牌配置。
- 主面板新增“全部静音”：全局安全静音叠加在每个 App 原有静音意图之上，关闭后未静音的 App 恢复播放，原本已静音的 App 继续保持静音。
- 正在播放但未启用音量管理的 App、全局静音开启后才开始播放的 App，以及切换输出中的会话都进入同一安全静音路径。
- 只读电平会话直接切换 process tap 的来源静音，先在旧会话上建立静音，再协调到 mixing，避免释放和重建之间漏出原声。
- 所有 mixing 会话通过统一入口下发增益、有效静音和音效，减少创建、输出切换、设备等待与恢复路径之间的状态分叉。
- 全局静音开启期间使用短周期只读轮询发现新播放 App；普通状态仍保持两秒轮询。自动化状态测试不代表真机漏音验收。
- 版本提升到 0.4.0（40）。

## 0.3.11 配置与文件边界

- 音效配置不可读只禁用音效编辑，不阻止基础应用音量、静音与明确选择的路由；仅靠音效接管的旧会话保留静音 tap 等待恢复，不能意外恢复原声。
- 自定义预设不可读时，手动 EQ、空间、动态、声道和内置预设仍可用；自定义预设操作单独禁用，并提供独立重新读取入口。
- 设置中增加更新残留检查与清理：完整读取镜像清单，清理前再次确认，只移除失效挂载标记，不自动卸载镜像或删除旧版本备份。
- App 与更新 helper 共用有界日志，当前日志和上一份日志各不超过 1 MiB，跨进程写入使用同一文件锁。
- 构建前归档已退出的旧 `dist/Auxmo.app`，不生成路径别名；检查文件是否仍被进程使用，拒绝移动或替换运行中的构建。
- 本地构建改为 `dist/build/debug/Auxmo.app` 和 `dist/build/release/Auxmo.app`；发布产物按版本、架构放入 `dist/releases/<version>/<arch>/`，不再共用一个应用包。
- 音效与自定义预设的坏记录不再解释成空配置，禁止覆盖并提供明确重新读取入口；配置保存不会清除其他配置或音频处理错误。
- 设置值无法解析时保持未选中，不启动对应可选功能；只有新电量来源键不存在时才迁移旧布尔设置。
- 更新解包显式报告清理和镜像卸载失败；未确认卸载时保留挂载记录与路径，阻止下一轮清理删除现场。
- 分离配置状态、音效编辑和电平计时器的所有权，按职责整理应用源码；音频会话仍由统一入口协调创建与释放。
- 应用路由配置损坏时，不再按“全部输出”处理或覆盖坏记录；停止新增接管，已有混音会话暂停重放并保留原声静音。修复配置后可明确重新读取。
- 输出设备必须按当前 UID 确认身份；找不到原设备时不沿用旧 ID，避免系统复用 ID 后选中无关输出。
- 自动更新不再移除 `com.apple.quarantine`，保留 macOS 的安全检查。
- 更新失败分别记录安装与恢复错误；恢复失败保留旧版本备份及路径，后续下载或跳过更新也不能自动删除该备份。启动命令成功后的清理失败不再触发回滚。

## 0.3.10 退出与清理可靠性

- 自动保护的静音写入与读回确认分开：HAL 已接受写入但尚未读回时限时等待同一设备，不重复写入、不立即锁存路由失败；旧目标离开或句柄变化时不沿用过期确认。
- 多设备组少一台时，继续在应用原先选中的在线目标上播放；不静音剩余成员，不扩大自定义目标范围。
- 系统意外切到选中范围外的真实输出时，只静音该接替设备；重连不自动取消静音，明确选择输出不触发这项保护。
- 修复已知音频进程属性读取恢复后，应用仍保留旧错误并一直暂停的问题；仅同一会话、进程和精确路由可自动恢复，真实处理与清理错误不清除。
- 重构应用音频资源生命周期：启动与切换共用创建链，按聚合已创建、回调已注册、运行中逐步推进；清理失败保留句柄，重试从未完成的一步继续。
- 清理遇到 `!dev` / `!obj` 时，必须完整枚举确认对应对象已消失才继续，不能只凭错误码释放回调内存。
- 修复应用静音捕获更新失败时错误详情为空、界面只剩应用名冒号的问题。
- 退出最多等待三秒确认系统释放；真实失败或超时会提供取消与仍然退出两个选项，并说明原声可能恢复。退出期间不创建新会话，取消尚未开始的路由请求；非完整清理会撤销更新与重启。
- 路由入口固定使用路由图标，等待设备时不再变成暂停按钮。

### 0.1.1 实机反馈修复

修正短 RPC 响应：明确解析 5 字节（8 位错误码）与上游测试记录的 6 字节（LE16 错误码）格式。保留其他长度错误的严格拒绝，并显示帧类型、预期长度与实际长度。协议诊断最多保留最近 24 条，每条接收数据最多显示 64 字节，只在本机内存与界面存在；分享前请自行检查内容。

### 0.1.2 应用音量可用性修正

修正旧版在组装列表前过滤所有 `isRunningOutput == 0` 进程，导致播放器暂停时整块空白的问题。普通应用身份来自 NSWorkspace，注册音频对象来自 Core Audio，播放活跃只作为状态，不再作为列表存在条件。

滑杆/静音配置、管理意图、已启动会话、失败锁存分别建模；无音频对象就明确等待，有对象后才创建 tap。首次处理从零淡入所设增益，避免先输出 100% 再调低。权限不足、输出不支持、资源释放失败等错误不会被其他捕获方式替代。

只读应用诊断：

```sh
./dist/Auxmo.app/Contents/MacOS/Auxmo --diagnose-applications
```

报告包含真实运行 App、归属的音频进程、对象 ID 和活跃标记。它不启动捕获、不申请录制权限，也不提供未经验证的“已授权”结论；分享前请自行检查本地应用身份信息。

### 0.1.3 界面精简

主界面仅保留输出、音量、应用与耳机操作，移除标语、开发标识、统计和常驻说明。待应用配置及真实错误仍保留；正常运行状态放在悬停提示中。顶栏只保留一个更多菜单；版本、打开控制窗口、立即刷新、音频录制权限入口与“复制耳机诊断”均收在其中。只调整表现层，不改变音频和耳机协议逻辑。

### 0.1.4 只显示播放中的应用

根据用户明确要求，界面仅展示 `isRunningOutput == true` 的应用。后台归属目录与展示列表分开，不能因隐藏暂停行而停止管理或重置配置；恢复播放后重新显示。当前使用系统音频输出活动标记，不用是否运行、是否注册、是否受管理来代替播放条件。只读 `--diagnose-applications` 仍报告完整后台目录，不能把它的总行数当成界面可见行数。

### 0.1.5 耳机自动识别

当前系统默认输出为 Px7 S3 时，包括启动时已连接的耳机，自动发现并建立本地控制通道。已验证的输出 UID→BLE UUID 绑定跨 Auxmo 重启保留；没有绑定时收集至少 2 秒广播，仅自动选名称规范化后完全相同的唯一候选，不按信号强弱挑选，不猜泛化广播。首次需要手动确认时，选一次、读取成功后即可记住。

- 音乐设备的配对/音频连接仍由 macOS 负责，Auxmo 不替你切换系统输出。
- 主动“断开/取消”会抑制本次音频连接期间的自动连接；切走输出再切回或明确点连接可恢复。
- 意外 BLE 断连按 2/5/10 秒最多重连 3 次；RPC 拒绝、解码错误、扫描超时、权限拒绝不会无限重试。
- 休眠停止扫描和控制，唤醒后根据真实输出恢复。没有恢复降噪/透传预设，也没有自动发出 SET。
- 右上角耳机选项的“重新选择耳机”是明确的手动身份更新，不是自动失败后猜别的设备。

显式硬件验收命令（会扫描蓝牙、连接控制、只读电量与降噪，退出前断开；不要与另一份 Auxmo 或耳机控制工具同时运行）：

```sh
./dist/Auxmo.app/Contents/MacOS/Auxmo --diagnose-headphones
```

退出码：0=真实读取确认；2=需要首次选择；1=失败/超时。该诊断与正常 App 共用控制器和绑定，不创建第二个 AppModel、不发设置命令。

- 系统输出暂时读取失败时，保留用户主动断开和连接失败记录，避免恢复读取后立即误触发重连。
- 应用只读诊断增加原始音频进程、归属信息及读取错误；耳机诊断增加独占检查，避免与运行中的 Auxmo 同时连接耳机。

### 0.1.7 耳机驱动与身份验证

- 复用 HeadBridge 的 B&W PX/PI 家族识别、Sony MDR V1 和 OPPO Enco 协议与传输；保留第三方来源和 MIT 许可。
- 修正旧 BLE UUID 绑定导致耳机停在选择阶段的问题。发现唯一候选后自动连接，并核对耳机硬件地址与当前系统输出；身份不匹配时明确报错，不改连其他候选。
- 传输中断采用有次数限制的重连；权限拒绝、身份不匹配和协议错误不会被自动绕过。
- 界面显示真实设备名、电量及已确认的噪声模式；修改模式后等待耳机回读确认，不提前显示成功。

本版接入驱动不等于完成所有型号的实机验证，Sony/OPPO 未经本机硬件验收。不支持 Sony V2，未知 OPPO 型号不启用降噪写入。

### 0.1.8 单行实时电平

面板默认 440pt 宽，与 Magpie 的标准面板宽度一致，采用浅灰平铺列表。各内容页独立测量；主动切页时按目标页高度调整外框，停留期间的异步状态和新内容通过内部滚动展示，隐藏耳机页不会撑高 APP 页。菜单栏使用固定锚点的自持有浮层，不通过 NSPopover 逐帧重定位。浮层直接显示和收起，不使用弹出、缩放或淡入动画，也不绘制顶部箭头；只有主动切页保留内容和高度过渡；内容淡入淡出只作用于透明度，不把动画事务传给滚动容器或控件布局，窗口高度仅由 AppKit 插值，避免双重布局动画造成上下抖动。选中块使用 0.14 秒、外框通过 AppKit 原生 animator 使用 0.24 秒无回弹缓出（不再自行逐帧 setFrame），快速反向切换从当前高度继续；系统启用减少动态效果时直接切换。原生滚动容器不显示横竖拖动条，但保留滚轮和触控板滚动。顶部使用“输出 / 麦克风 / 耳机控制”三个同级页签，不再保留二级设备切换。输出页列出全部输出设备，分别读取和控制硬件音量与静音；只有点击设备名称才切换默认输出。未公开硬件属性的设备明确显示不支持，不切换其他后端、不填入默认音量。麦克风页列出系统输入设备，可切换默认麦克风、调节输入音量与硬件静音，不采集或录制输入音频，不提供未经实现的按 APP 麦克风增益。输出页与麦克风页下方保留相同的 APP 播放音量区；耳机页只保留耳机功能，不重复展示设备音量或 APP 列表。应用行按“电平、图标、名称、静音、滑杆、百分比”排列，重试与停止管理移到右键菜单，不保留三个点。电平表为 10×20pt，音量条采用细轨道，支持键盘与辅助功能调整。峰值用 -60…0 dBFS 对数刻度，不是系统音量或扬声器声压；已管理时位于 Auxmo 增益/静音之后。自动只读计量只在应用音量面板可见、对应 App 正在播放且没有失败时启用，仍需系统音频录制权限；不写文件或上传。实时回调仅计算峰值并写预分配原子邮箱，界面以 30Hz 消费并平滑回落。错误保留为同行图标、悬停与菜单，计量失败可以单独重试，不能借重试电平擅自启用音量管理。


### 0.1.9 首次权限

蓝牙授权通过 CoreBluetooth 管理器触发；系统音频没有独立的公开授权查询/申请函数，使用一个私有、unmuted、无物理输出的短生命周期 tap 输入触发系统申请后立即释放。回调忽略全部输入，不保存或重放音频，也不改变现有输出或音量。不使用私有 TCC 或屏幕录制授权替代这项权限；已有决定不强制重置。正常主模型在申请入口执行且探测资源已释放后才构造；探测资源清理失败只报告错误并退出，不继续留着采集输入运行；只读命令行诊断不执行该流程。蓝牙关闭且尚未发生决定时不阻塞启动，下次启动仍可申请。用户可以拒绝；调用成功和本地首次标记都不构成已授权证明。

Apple 要求保留用途说明：[蓝牙](https://developer.apple.com/documentation/bundleresources/information-property-list/nsbluetoothalwaysusagedescription)、[系统音频与 tap](https://developer.apple.com/documentation/coreaudio/capturing-system-audio-with-core-audio-taps)。当前分别为“用于控制蓝牙耳机。”和“用于调节应用音量。”。
